# Data Model: Dashboard Builder

**Spec**: [spec.md](./spec.md) | **Constitution**: §3.3, §5, §6, §7.4, §7.6, §7.7

## Overview

Feature 6 adds tenant/workspace-scoped **dashboards**, **dashboard_widgets**, and **dashboard_grants**. It reuses **collections** for inheritance, **saved_questions** as widget data sources, **asset_grants** for external-client dashboard access/export, and Feature 4 **query_audit_logs** / **cache_entries** for widget execution.

FastAPI resolves membership, merges dashboard filter state, validates bindings against saved-question parameter schemas, and delegates execution/export to the query engine `widget` mode.

## Entity: `dashboards`

Workspace analytical canvas in exactly one collection.

| Column | Type | Notes |
|--------|------|-------|
| `id` | UUID PK | Generated by database |
| `tenant_id` | UUID NOT NULL | FK → `tenants.id` |
| `workspace_id` | UUID NOT NULL | FK → `workspaces.id` |
| `collection_id` | UUID NOT NULL | FK → `collections.id` |
| `title` | TEXT NOT NULL | Unique within collection after trimming |
| `definition` | JSONB NOT NULL | Global filters, layout version, builder metadata |
| `created_by_membership_id` | UUID NOT NULL | FK → `memberships.id` |
| `updated_by_membership_id` | UUID NULL | Last editor membership |
| `created_at` | TIMESTAMPTZ NOT NULL | Default `now()` |
| `updated_at` | TIMESTAMPTZ NOT NULL | Stale-update guard |
| `deleted_at` | TIMESTAMPTZ NULL | Soft delete marker |

**`definition` JSON shape (authoritative fields)**

```json
{
  "layout_version": 1,
  "global_filters": [
    {
      "id": "gf_region",
      "label": "Region",
      "value_type": "string",
      "default_value": "EMEA"
    }
  ]
}
```

- `global_filters[].id` is stable within the dashboard and referenced by widget `filter_bindings` / `filter_overrides`.
- `default_value` is analyst-authored; MUST NOT be derived from viewer identity.
- Widget-local-only filters are forbidden.

**Constraints & indexes**

- UNIQUE `(collection_id, lower(trim(title)))` for active rows where `deleted_at IS NULL`.
- FK `(tenant_id, workspace_id, collection_id)` → `collections`.
- Index `(tenant_id, workspace_id, collection_id, deleted_at, title)`.
- Index `(tenant_id, workspace_id, deleted_at, updated_at DESC)`.

**Validation rules**

- Title non-empty after trim; duplicate active titles within the same collection rejected.
- `collection_id` must reference an active collection in the same tenant/workspace.
- Collection delete refused while active dashboards remain.
- Updates must include last-known `updated_at`; stale updates rejected.

## Entity: `dashboard_widgets`

Normalized widget row belonging to one dashboard.

| Column | Type | Notes |
|--------|------|-------|
| `id` | UUID PK | Stable widget identity for execute/export/audit/cache |
| `tenant_id` | UUID NOT NULL | FK → `tenants.id` |
| `workspace_id` | UUID NOT NULL | FK → `workspaces.id` |
| `dashboard_id` | UUID NOT NULL | FK → `dashboards.id` |
| `saved_question_id` | UUID NOT NULL | FK → `saved_questions.id` |
| `widget_type` | ENUM/TEXT NOT NULL | `kpi`, `bar`, `line`, `table` |
| `title` | TEXT NULL | Optional widget chrome label |
| `layout` | JSONB NOT NULL | Grid position `{x,y,w,h}` and display order |
| `config` | JSONB NOT NULL | Chart options, axis mapping, optional TTL lowering |
| `filter_bindings` | JSONB NOT NULL | Map `global_filter_id` → `parameter_name` |
| `filter_overrides` | JSONB NOT NULL | Map `global_filter_id` → override value; empty object when none |
| `created_at` | TIMESTAMPTZ NOT NULL | Default `now()` |
| `updated_at` | TIMESTAMPTZ NOT NULL | Widget-level updates |
| `deleted_at` | TIMESTAMPTZ NULL | Soft delete marker |

**Constraints & indexes**

- FK `(tenant_id, workspace_id, dashboard_id)` → `dashboards`.
- FK `(tenant_id, workspace_id, saved_question_id)` → `saved_questions`.
- Index `(dashboard_id, deleted_at)`.
- Index `(tenant_id, workspace_id, saved_question_id)`.

**Validation rules**

- `widget_type` limited to `kpi`, `bar`, `line`, `table`.
- `filter_bindings` keys must reference existing `definition.global_filters[].id`.
- `filter_overrides` keys must reference existing global filters; values must satisfy bound parameter types on the linked saved question.
- Absence of a binding means the widget ignores that global filter.
- Overrides must not introduce keys absent from global filters (no widget-local-only filters).
- `config.ttl_seconds` MAY lower refresh interval per widget type class ceiling; MUST NOT exceed platform TTL defaults.
- Author must have access to `saved_question_id` at configure time; execute re-checks access.

## Entity: `dashboard_grants`

Internal per-dashboard widen beyond inherited collection access.

| Column | Type | Notes |
|--------|------|-------|
| `id` | UUID PK | Generated by database |
| `tenant_id` | UUID NOT NULL | FK → `tenants.id` |
| `workspace_id` | UUID NOT NULL | FK → `workspaces.id` |
| `dashboard_id` | UUID NOT NULL | FK → `dashboards.id` |
| `membership_id` | UUID NOT NULL | FK → `memberships.id` |
| `permission` | ENUM/TEXT NOT NULL | `view` or `edit` only |
| `created_by_membership_id` | UUID NOT NULL | Granting membership |
| `created_at` | TIMESTAMPTZ NOT NULL | Default `now()` |

**Constraints & indexes**

- UNIQUE `(dashboard_id, membership_id)`.
- FK `(tenant_id, workspace_id, dashboard_id)` → `dashboards`.
- Index `(tenant_id, workspace_id, dashboard_id)`.

**Validation rules**

- Grants widen only; never deny collection-inherited access.
- Export is not implied by `view` or `edit`.

## Reused entities

### `asset_grants` (Feature 2 / 5)

External-client access to dashboards:

- `asset_type = dashboard`
- `asset_id = dashboards.id`
- `can_export` controls table widget CSV export

### `saved_questions`

Widgets reference saved questions for SQL and `parameter_schema`. External clients and viewers never receive `sql_text` through dashboard responses.

### `query_audit_logs` / `cache_entries` (Feature 4)

Widget execution populates `dashboard_id`, `widget_id`, `saved_question_id`, and uses `filter_state_hash` in cache identity.

## Permission resolution

Effective dashboard access for internal roles:

1. Resolve collection grant for the dashboard's `collection_id`.
2. Widen with `dashboard_grants.permission` if present (`edit` wins over `view`).
3. `admin` / `analyst` retain implicit edit when authorized by product rules in service layer.

External clients:

1. MUST have explicit `asset_grants` row for the dashboard.
2. MUST NOT inherit collection access.

Export permission:

- Internal `admin` / `analyst` / `viewer`: same rules as saved questions for visible dashboards.
- External clients: `asset_grants.can_export = true`.

## State transitions

| Action | Preconditions | Result |
|--------|---------------|--------|
| Create dashboard | Actor can create in target collection | New row + optional initial widgets |
| Update dashboard/widgets | Actor has `edit`; `updated_at` matches | Metadata/layout/widgets updated; cache keys for affected widgets invalidated on binding/override/filter changes |
| Soft delete dashboard | Actor has `edit` | `deleted_at` set; hidden from lists |
| Clone dashboard | Read source; create in target collection | New dashboard + widgets; target collection permissions; no copied `dashboard_grants` |
| Execute widget | View access; valid merged parameters | Feature 4 widget execution + audit |
| Export table widget CSV | Export allowed; widget type `table` | Synchronous CSV capped at 10,000 rows |

## Cache invalidation triggers

Purge or bypass cache entries when:

- Dashboard global filter definition or default changes
- Widget `filter_bindings` or `filter_overrides` change
- Linked `saved_questions.sql_text` or `parameter_schema` changes (existing Feature 5 rule)
- Connection rotation (existing Feature 4 rule)
- User sets `bypass_cache=true` on execute/export

`filter_state_hash` MUST change when consumer filter values or active overrides change.
